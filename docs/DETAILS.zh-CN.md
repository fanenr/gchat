## 功能细节

### 对话布局

- 调整窗口宽度时，消息区与输入区保持对齐。
- 窗口最小尺寸请求为 640 × 480 逻辑像素。平台或内容可能要求更大的尺寸。
- 可用宽度不超过 760 逻辑像素时，内容占 85%；达到 1200 逻辑像素后占 75%。中间比例平滑过渡，两侧各保留至少 16 逻辑像素边距；极窄时优先保留边距。

### 流式回复

- 客户端用 libsoup3 异步读取 SSE，边生成边显示。多行 `data` 用换行符连接，在空行处处理事件。
- 生成中按钮变为停止键。点击后立即中断，已生成的正文与推理内容保留。
- 记录中只有推理内容时，客户端不把它作为空回复发送给 API。
- 布局完成后，流式内容与 Markdown 收尾跟随底部。
- 向上阅读时，视图不会自动跳回末尾。

### Markdown 渲染

- md4c 解析 Markdown，支持 CommonMark 与部分 GFM。
- 客户端把 Markdown 渲染成原生控件。
- 支持的控件有标题、粗体、斜体、删除线、行内代码、多层列表、嵌套引用、分隔线和表格。
- 列表支持任务列表与有序列表。有序列表可以从 0 开始。
- 表格支持列对齐、行分隔线和行内代码。
- 表格外的 HTTPS 图片自动加载。图片服务器可以看到你的 IP 地址和请求时间；客户端不筛除内网 HTTPS 地址。流式回复结束后开始加载；重新渲染历史消息时会再次加载。
- 图片使用独立请求，不携带 API 凭据。系统解码器可用时支持 PNG、JPEG、GIF 和 WebP；GIF 和 WebP 显示为静态图片。
- 图片显示尺寸不超过 320 × 240 逻辑像素，保持宽高比，不放大小图。图片可能为消息设置最小宽度，极窄的布局不一定能容纳它。
- 图片请求不跟随重定向，20 秒超时。下载上限为 8 MiB，图片上限为 1600 万像素。加载失败或不支持的图片显示 `[alt 文本]`；alt 为空时显示 `[图片]`。
- 链接只打开 HTTP、HTTPS 和 mailto。
- 本地文件、相对链接和其他应用协议只显示文字，客户端不唤起外部程序。

### 图片输入

- 点击附件按钮可多选本地图片，也可在输入框粘贴图片、截图或复制的多个本地图片文件。每次导入都会追加到当前草稿。
- 在输入框内的缩略图栏预览附件。图片较多时可横向滚动。点击缩略图上的关闭按钮可单独移除该图。
- 剪贴板同时含有图片和文字时优先添加图片；纯文字仍按原方式粘贴。粘贴的图片像素会转成 PNG，元数据不保证保留；粘贴的图片文件按原内容保存。
- 可以发送纯图片消息。图片显示在消息中，普通草稿和编辑草稿分别保存图片。
- 系统解码器可用时支持 PNG、JPEG、GIF 和 WebP。按文件内容判断格式，GIF 和 WebP 预览为静态图片。
- 单张图片最多 8 MiB，最长边最多 8192 像素，总像素最多 1600 万。粘贴图片像素的大小按转成 PNG 后计算；GTK 可能在客户端检查尺寸前解码图片。每次请求最多 600 张图；达到 15 张时，所有图片的最长边最多 4096 像素。这两项限制包含历史图片。完整请求体最多 48 MiB，包含历史图片及 Base64 编码开销。
- 图片随历史在每次请求中发送，可能增加等待时间和费用。选择的文件原样发送，包括可能存在的元数据。
- 图片只能通过 `deepseek-flash` 发送。如果当前消息或历史含图片，其他模型不能发送或重新生成；请切回 Flash。
- 当前批次读入完成后，才能继续添加图片或发送。切换会话、进入或取消编辑会取消当前读入。同批有任一文件无法导入时，整批不添加。图片丢失或请求超限时，客户端提示，不提交当前草稿。
- 图片副本保存在数据目录的 `attachments/`，权限为 `0600`，不加密。编辑、复制和分叉会保留图片引用。
- 客户端启动并成功读取数据库后，清理 `attachments/` 中未被引用的图片。不扫描旧的 `images/` 目录。
- 暂不支持拖放图片。请求构造和历史预览会在界面线程读取图片；长对话可能出现短暂停顿。

### 代码块

- 代码块显示为独立卡片，带语言标签和复制按钮。
- 代码区上下间距各 8px。
- 显示时只省略末尾的一个换行。额外空行不裁剪。
- 复制按钮保留解析后的完整代码，含行尾空格和末尾换行。
- md4c 把块内容的换行统一为 LF。
- 高亮由 GtkSourceView 负责。可用语言取决于安装的版本。
- 配色随深浅主题在 Adwaita 与 Adwaita-dark 之间切换。

### 多会话

- 左侧会话列表先显示置顶会话，其余按「今天 / 昨天 / 更早」分组。各组按创建时间从新到旧排列。
- 顶部一行是「新对话」按钮。会话行尾悬停时出现删除键。右键菜单可置顶、取消置顶、复制或重命名会话。
- 复制会打开一个未置顶的新会话，独立保留消息、推理和草稿，包括正在编辑的内容。
- 历史、当前会话、模型、推理级别和各会话草稿保存在 `~/.local/share/gchat/session.db`。
- 历史包含推理内容和思考用时。
- 删除会话前必须确认，默认动作为取消。
- 删除会话时，客户端同时删除该会话的消息和草稿。
- 侧栏搜索按标题和正文做本地、不区分大小写的字面匹配。
- 正文命中时，客户端显示附近摘要。
- 搜索不覆盖推理内容和草稿。

### 设置

侧栏底部的齿轮入口打开设置页，提供以下项目：

- API 密钥。
- 主题。可选跟随系统、浅色、深色。切换后即时生效并持久化。
- 界面语言。
- 版本与数据文件位置。

### 模型与推理级别

- 模型有 `deepseek-flash` 和 `deepseek-v4-pro`。
- 推理级别有 `none`、`low`、`high`、`max` 四级。
- `none` 关闭思考，对应 `thinking.type=disabled`。
- 客户端把模型与推理级别合成为一个 chip，放在输入框右下角。
- 点击 chip 弹出分组菜单。
- 思考时展开推理内容，开始回答或停止生成时自动折叠。也可以手动展开或折叠。完成后的推理内容显示为「已思考（用时 x 秒）」。

### 消息操作

最新一条消息始终显示操作行。其他消息在鼠标悬停，或消息及其控件获得焦点时显示操作行。操作包括：

- 整条复制。
- 编辑后重发。客户端把正文放回输入框，发送时才撤回该条及之后的消息。
- 分叉为新会话。选择用户消息时，新会话保留之前的历史，并将该消息放入草稿。选择助手回复时，保留到该回复为止的历史，包括推理内容。原会话不变。分叉不会发送请求，生成期间不可分叉。
- 重新生成。只对最后一条回复可用。
- 删除单条消息。

规则如下：

- 编辑期间不得重新生成。
- 切换会话或重启客户端后，编辑状态恢复。
- 点击「取消」，或在输入框按 `Esc`，恢复原普通草稿。
- 用户消息和回复都按 Markdown 渲染。贴回的代码块、表格和列表正常显示。
- 发送时保留正文缩进与末尾空白。没有图片时，客户端拒绝纯空白消息。
- 用户气泡按正文宽度收缩。内边距固定为左右各 16px、上下各 10px。
- 操作行不撑宽底色。多行文字保持左对齐。
- 可以跨段落拖动选择，可以用 `Ctrl/Cmd+A` 全选本条。
- 代码块另有单独的复制按钮。

### 可靠性

- 客户端在同一个 SQLite 事务内保存会话变更、删除操作和当前会话状态。
- 校验内容包含唯一会话 ID、消息类型、附件 ID 和编辑目标。
- 数据库无法加载时，客户端报错并停止。不重建数据库，也不自动恢复备份。
- 同一数据目录由一个进程持锁写入。
- 重复启动时，第二个进程提示锁定失败并退出。两个进程不会相互覆盖。
- 请求失败时，客户端显示带「重试」按钮的 toast。
- 切到其他会话后，旧 toast 不会重试当前会话。
- 生成中关窗或退出应用时，客户端保存已收到的正文与推理。
- 重复的退出通知不会再次保存。
- 关窗保存失败时，客户端保留窗口，不丢弃内存中的草稿。
- 应用级退出无法中止时，客户端报告保存失败并返回非零状态。

### 错误处理

- HTTP 错误和网络错误用纯文本 toast 提示，并附响应体摘要。
- 客户端不解释错误内容中的标签。
- 客户端异步读取错误正文。读取可以取消，不阻塞界面。
- 失败时不留完全空白的消息。
- 会话或配置写盘失败时，客户端提示。
- 主题和语言保存失败时，客户端恢复原选择。

### 草稿

- 每个会话独立保存普通草稿与编辑草稿。编辑草稿是编辑消息时暂存的正文。
- 输入停顿 750ms 后，客户端自动写盘。
- 切换会话、发送消息或正常退出时，客户端立即保存。
- 生成期间保存草稿时，同一事务也保存已收到的正文与推理。
- 编辑重发后，客户端恢复原普通草稿，不把草稿发送给 API。
- 新建的空会话有草稿时，「新对话」按钮另建一份空会话。

输入框下方常驻「内容由 AI 生成，请仔细甄别」。

### 界面语言

客户端支持 English 和简体中文。

- 默认跟随系统语言。
- 系统语言不受支持时，客户端回退到英语。
- 简体中文匹配 `zh_CN`、`zh_SG`、`zh-Hans` 和通用 `zh`。
- 繁体中文回退到英语。

在「设置 → 外观 → 语言」中选择「跟随系统 / English / 简体中文」。
选择保存在 `~/.config/gchat/config.json` 的 `language` 字段。
字段值为 `system`、`en` 或 `zh_CN`。选择在**重启客户端后生效**。
保存失败时，客户端提示并恢复原选择，不改变输入草稿或生成状态。

界面文案、操作提示和错误提示使用 gettext。
以下内容不翻译：

- 消息正文。
- 推理内容。
- 已有会话标题。
- DeepSeek 返回的错误正文。

客户端也不会通过 API 强制模型使用某种语言回复。
新会话的空标题在显示时翻译。客户端不把界面语言写入会话标题。

翻译目录为 `po/`。英语原文在 C 和 Blueprint 文件中，简体中文译文在 `po/zh_CN.po`。
`po/POTFILES` 列出这些文件；Blueprint 字符串使用与 C 相同的 `_()` 语法。
构建需要 gettext 的 `msgfmt`。
编译后的词典位于构建目录的 `po/` 下，运行时必须保留此目录。
只复制单个 `gchat` 可执行文件无法运行。
更新翻译模板和词典：

```sh
meson compile -C build gchat-update-po
```

## 存储

文件位置、备份、数据库格式和升级流程见 [gchat 存储](STORAGE.zh-CN.md)。

## 回归测试

测试代码统一放在 `tests/`，分工如下：

- `test-app.c`：SSE 解析，模型与推理级别的查找。
- `test-store.c`：SQLite 存储、升级和配置。
- `test-md.c`：Markdown 渲染。
- `test-i18n.c`：语言匹配、英语回退、手动选择，以及 C locale 下的词典加载。

应用测试分别以英语和简体中文运行。检查内容包括：

- 设置文案。
- 实际配置路径。
- 版本信息。
- 保存失败时的回退。
- 切换语言后草稿和会话状态不变。

配置测试验证合并写入不生成密钥备份。
中文搜索输入测试用独立 IM 模块模拟提交时序。检查内容包括：

- 预编辑通知。
- 前缀、选区和中间插入。
- 实际光标布局。
- 搜索结果。
- 输入法上下文生命周期。

翻译文件另有格式校验。

回归测试的其他覆盖范围如下：

- 数据库初始化、重新打开和拒绝不支持的版本。
- 增量写入、升级或保存失败时回滚、图片清理。
- 会话结构校验，包括非法消息角色和编辑目标。
- 进程锁。
- 损坏配置保护。
- 主题和语言保存回退。
- 应用退出与关窗保存失败。
- 重复退出。
- 生成中快照和过期请求回调。
- 过期重试。
- 错误正文纯文本显示。
- 编辑保护。
- Markdown 行内样式作用域与语言别名。
- 推理保存与请求过滤。
- 慢速 HTTP 错误正文和取消。
- SSE 字段类型、多行事件、CRLF 和未完成事件。
- 列表序号与首段位于同一行。
- 从 0 开始的有序列表。
- 多段和嵌套列表。
- Markdown 跨控件作用域。
- 消息与代码块末尾空白。
- 外链协议过滤与实体解码。
- 代码块缓冲区释放。

代码块内容测试从 Markdown 输入验证显示与复制。覆盖围栏、缩进代码、原始 HTML 块、
CRLF、未闭合围栏、空块和额外空行。
布局测试在深浅主题下检查底部间距和末行可见性，覆盖单行、多行和长行折行。
布局用例显示独立测试窗口，检查气泡换行、固定内边距和短句居中。
用例还在已显示的窗口中重建用户气泡，检查高度不被旧测量缓存撑大。
本机流式用例点击真实「重新生成」按钮。检查生成期间、收尾和历史重渲染后的气泡布局。
测试同时检查向上阅读与输入框变化后的实际可见末尾，不只检查滚动数值。
测试只使用临时目录和本机 HTTP 服务。测试不访问 DeepSeek，也不读取用户会话或密钥。

GTK 相关测试需要显示后端。后端不可用时，测试跳过。

## 代码结构

| 文件 | 职责 |
| --- | --- |
| `meson.build` | 项目版本、构建目录配置、应用与各测试的直接依赖。版本号同步用于关于页和 User-Agent |
| `main.c` | 窗口布局、侧边栏与消息区、设置面板、流式请求与取消、会话保存与退出生命周期 |
| `ui/` | Blueprint 布局、CSS 和 GResource 清单。布局编译为 GtkBuilder XML 并嵌入应用 |
| `i18n.c` / `i18n.h` | 启动时的语言匹配与 gettext 初始化 |
| `po/` | gettext 翻译模板、简体中文词典与构建规则 |
| `md.c` / `md.h` | md4c 回调转换为 GTK 控件。正文与表格共享行内样式和文本解码 |
| `store.c` / `store.h` | SQLite 会话校验、升级和事务、进程锁、配置校验与合并写入 |
| `tests/` | 会话存储、应用状态与请求、Markdown 渲染的回归测试 |

## 已知限制

- macOS 输入法在部分情况下于提交前清空预编辑文本，并在提交后才通知 GTK。
  搜索框在提交前同步已清空的预编辑状态。状态与提交钩子随对应输入法上下文销毁。
  客户端不禁用输入法。
- 表格内的图片只显示 `[alt 文本]`。单元格支持行内代码，但不支持多行代码块。
- 公式（`$…$`）按原文显示。
- 代码高亮按 GtkSourceView 语言 ID 和显式别名查找，例如 `javascript` 对应 `js`，
  `csharp` 对应 `c-sharp`。
- 未识别的语言名按纯文本显示，客户端不做近似匹配。
- 选区不能跨消息。GTK 的选中范围限于单个控件。代码块和表格是独立控件，拖选在那里断开。
- SSE 事件的数据须符合 DeepSeek JSON 格式，结束标记为 `[DONE]`。
  客户端忽略无效 JSON，也不处理 `event`、`id` 和 `retry` 字段。
  未以空行结束的事件会被丢弃。此实现不是通用 SSE 客户端。
- 客户端只解码常用命名实体和数字实体。不在实体表中的命名实体保留原文。
- 草稿自动保存有 750ms 延迟。强制结束进程会丢失尚未提交的输入或流式回复。SQLite 事务不能替代独立备份。
