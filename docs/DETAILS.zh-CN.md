# gchat 实现细节

[English](DETAILS.md) | **简体中文**

本文说明 `gchat` 的代码结构、核心机制、打包方式、测试套件和已知限制。数据路径、数据库结构与格式升级见[存储](STORAGE.zh-CN.md)。

## 代码结构

| 路径 | 职责 |
| --- | --- |
| `meson.build` | 项目版本、构建目标与依赖声明 |
| `main.c` | 主窗口、侧栏、消息列表、设置弹窗、HTTP/SSE 生命周期与退出流程 |
| `md.c` / `md.h` | `md4c` Markdown 解析器、原生 GTK4 控件渲染器、代码块卡片、表格与远程图片加载器 |
| `store.c` / `store.h` | SQLite 会话存储、格式升级、单实例进程锁与 `config.json` 原子写入 |
| `i18n.c` / `i18n.h` | 启动时的语言环境匹配与 `gettext` 初始化 |
| `macos-bundle.c` / `macos-bundle.h` | macOS `.app` 包内的资源、词典、图标与 TLS 信任库初始化 |
| `ui/` | Blueprint 界面定义、CSS 样式与 `GResource` 清单 |
| `po/` | `gettext` 翻译模板（`POTFILES`）与简体中文词典（`zh_CN.po`） |
| `packaging/` | macOS DMG 打包脚本与 Linux Flatpak 清单和元数据 |
| `tests/` | 回归测试套件（`test-app.c`、`test-store.c`、`test-md.c`、`test-i18n.c`） |

## 核心机制

### 请求与流式输出

- **SSE 流式读取**：`main.c` 使用 `libsoup3` 异步读取 SSE。解析器合并多行 `data:` 字段，并在空行处分发事件。正文和推理内容增量按 GTK 帧时钟合并，每帧最多刷新一次界面。
- **历史消息回传**：请求按顺序发送生效的系统提示词、摘要以及摘要未覆盖的用户与助手消息（含图片附件）。无摘要时，`gchat` 发送截至当前轮次的完整历史。请求不包含未发送草稿和已保存的 `reasoning_content`。
- **用户元信息**：该开关默认关闭。开启时，`gchat` 为每条新用户消息保存 `latest_reminder` 并在该消息前发送。其内容包含本地日期、星期、`App` 和当前界面语言，位置为空。关闭时，`gchat` 不发送任何 `latest_reminder`。没有该字段的旧消息保持为空，重新生成时也不补填。
- **联网搜索与网页阅读**：仅支持 `deepseek-flash`。开启时，DeepSeek 服务端可以调用搜索与网页读取工具。流式输出期间，`gchat` 显示工具进度，并在回复下方渲染去重后的 HTTP/HTTPS 引用来源。后续 `deepseek-flash` 请求回传 `server_tool_calls`，保留已读网页上下文。
- **自动标题**：未命名的 `deepseek-flash` 会话首次发送时，`gchat` 取用户首行文本作为临时标题。流式响应结束并返回服务端标题时，`gchat` 替换该临时标题。

### 上下文管理

- **系统提示词**：会话默认继承全局系统提示词，也可以自定义或明确省略。生效提示词非空时，`gchat` 将其作为第一条 `system` 消息发送，重新生成时同样生效。
- **压缩范围**：手动与自动压缩均按配置保留最近若干轮用户原文（默认 2 轮）。自动压缩时，待发送的新消息不计入保留轮数，按原文发送。修改该设置不改变已有摘要。
- **摘要请求**：`gchat` 发起一次独立的非流式 `deepseek-flash` 请求，将早期消息、图片附件和已有摘要压缩为新摘要。该请求关闭推理与联网工具，不包含会话的系统提示词、推理内容和 `server_tool_calls`。
- **保存与回传**：`gchat` 保存摘要文本及其覆盖的原始消息数。后续请求将摘要作为历史上下文发送，不作为系统提示词。原始消息和附件保持不变。分叉会话包含摘要覆盖的全部消息时，才继承该摘要。
- **压缩标记与只读范围**：默认折叠的「上下文已压缩」标记记录压缩发生的位置，与摘要覆盖的消息数相互独立。手动压缩把标记加到消息末尾并滚到底部。自动压缩把标记插在待发送的新消息之前。点击标记可以展开或收起摘要。即使没有被摘要覆盖，标记之前的所有消息均为只读：`gchat` 隐藏这些消息的编辑、删除和重新生成操作，并阻止重试标记前的轮次。用户仍可以复制或分叉这些消息。
- **自动触发与估算校准**：自动压缩默认关闭。开启时，`gchat` 在发送前比较输入 token 估算值与配置阈值。流式聊天请求通过 `stream_options.include_usage` 获取用量。DeepSeek 返回 `usage.prompt_tokens` 后，`gchat` 用同一会话、同一模型最近一次的实测值在内存中校准估算。编辑模式不使用校准数据；切换模型后，必须等新模型返回用量才恢复校准。压缩阈值不是模型上下文上限。
- **上下文圆环**：圆环及弹出层估算下一次请求大小，涵盖生效的系统提示词、摘要、活跃历史、当前草稿和附件图片（每张按 1,024 token 计算）。编辑消息时，只统计该消息之前的历史。即使自动压缩关闭，圆环仍以压缩阈值为基准。圆环弧线在 100% 封顶，百分比文字可以超过 100%。达到 80% 时圆环变橙色，达到 100% 时变红色。
- **失败与取消**：压缩失败或取消时，`gchat` 保持原有摘要、历史消息和草稿不变。每次发送最多尝试一次压缩。最终发出的聊天请求仍受请求体大小与模型上限约束。

### Markdown 与媒体

- **原生控件树**：`md.c` 通过 `md4c` 解析 CommonMark 与 GFM 扩展，生成原生 GTK4 控件（正文用 `GtkTextView`，表格用 `GtkGrid`，代码块用带 `GtkSourceView` 的卡片）。在消息区空白边距或间隙中拖动可直接开始选择对应文本控件中的内容，单击空白区域则清除已有选区。
- **远程图片**：`gchat` 异步加载表格外的 HTTPS 图片，不附带 API 凭据，也不跟随重定向。外部链接仅打开 `http`、`https` 和 `mailto` 协议。
- **图片输入**：在 `deepseek-flash` 下，可以通过文件选择器或剪贴板添加 PNG、JPEG、GIF 和 WebP 图片。`gchat` 按 UUID 将图片复制到 `attachments/`，并在启动成功加载数据库后删除未引用的文件。

| 范围 | 限制 |
| --- | --- |
| 远程图片 | 总超时 20 秒、单图上限 8 MiB、总像素上限 1,600 万、显示上限 320 × 240 逻辑像素 |
| 单张上传图片 | 单图上限 8 MiB、单边上限 8,192 像素（单次请求达 15 张及以上时为 4,096 像素）、总像素上限 1,600 万 |
| 单次请求 | 最多 600 张图片、含 Base64 历史图片在内的请求体上限 48 MiB |

### 会话与草稿

- 每个会话独立保存消息列表、推理内容、普通草稿和编辑草稿。
- 输入停顿 750 ms 后触发自动保存。切换会话、发送消息或关闭窗口时，`gchat` 立即在单个 SQLite 事务内落盘。
- 编辑或分叉消息保留图片引用。在发送编辑后的消息前，`gchat` 不修改原有历史。
- 消息导航按顺序列出当前会话中显示的用户消息，搜索匹配消息全文。跳到历史消息会暂停自动跟随，点击「跳到最新消息」恢复跟随。

### 国际化

- `gchat` 支持 English 与简体中文（通过 `config.json` 的 `language` 字段配置为 `system`、`en` 或 `zh_CN`，重启后生效）。
- `i18n.c` 将 `zh_CN`、`zh_SG`、`zh-Hans` 和通用 `zh` 匹配为简体中文，其余语言环境（含繁体中文）回退到英语。
- 修改界面文案后，运行以下命令更新翻译词典：

  ```sh
  meson compile -C build gchat-update-po
  ```

## 打包

### macOS 应用包

`macos-arm64` 构建目标在临时目录组装 `gchat.app`，将非系统动态库及 GIO、gdk-pixbuf 模块复制到 `Contents/Frameworks`。脚本将 Mach-O 加载路径改写为包内相对路径，并在签名前校验依赖闭包。最低 macOS 部署版本取可执行文件与打包库中的最高值。

### Flatpak

[Flatpak 清单](../packaging/flatpak/io.github.fanenr.gchat.yml)基于 GNOME SDK 51 构建，传入 `-Dflatpak=true` 与 `/app` 前缀，并从带校验和的归档编译 `md4c`。沙箱开放网络访问、Wayland/X11 显示、文件选择与链接打开门户，以及宿主机目录 `xdg-data/gchat` 与 `xdg-config/gchat`。因此，Flatpak 版与原生构建共用同一份数据库和配置文件。

## 测试

`tests/` 下的回归测试在临时目录运行，不访问外部网络：

- `test-app.c`：SSE 解析、流式生命周期、请求体生成、联网搜索、自动标题、图片校验与会话状态转换。
- `test-store.c`：SQLite 初始化、格式升级、事务保存、进程锁、附件清理与 `config.json` 读写。
- `test-md.c`：Markdown 控件渲染、代码块、表格标记、链接过滤与图片辅助函数。
- `test-i18n.c`：语言环境匹配、回退规则与词典加载。

## 已知限制

- 表格单元格支持行内样式与行内代码，不支持多行代码块或内嵌图片（图片显示为 `[alt 文本]`）。
- LaTeX 公式（`$…$`）按源码文本显示。
- 文本选区限于单个 GTK 文本控件内，不能跨越代码块、表格或多条消息。
- 语法高亮按 `GtkSourceView` 语言 ID 及固定别名表（如 `javascript` → `js`、`csharp` → `c-sharp`）匹配，未知语言按纯文本显示。
- SSE 解析器面向 DeepSeek 的 JSON 数据流与 `[DONE]` 结束标记，不适用于任意 SSE 流。
- HTML 实体解码仅支持数字实体与常见命名实体表。
- 暂不支持拖放导入图片。编码包含大量历史图片的请求在界面线程执行。
- 草稿自动保存有 750 ms 防抖延迟，进程崩溃或收到 `SIGKILL` 时会丢失未提交的草稿与未完成的流式输出。
